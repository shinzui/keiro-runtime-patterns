# ADR 0008: Adopt OKF for the runtime pattern corpus

## Status

Accepted — 2026-07-22

## Context

The runtime standards form one cross-linked corpus, but they previously lived in
seven top-level directories with hand-maintained README indexes. Humans and
agents had to know a directory before discovering a document, metadata was held
only in Mori DocRefs, and no repository check connected a material document
change to a review timestamp or update record.

Open Knowledge Format (OKF) provides concept metadata, graph validation,
generated indexes, and scoped update logs. OKF recursively treats every
non-reserved Markdown file below a bundle root as a concept, so using the
repository root would incorrectly absorb plans, ADRs, MasterPlans, and agent
skills into the runtime catalog.

## Decision

Keep the normative corpus in one isolated OKF bundle at `runtime-patterns/`,
registered in Mori with the bundle name `runtime-patterns`. The seven subject
directories stay together so cross-subject links remain one validated graph.
Plans, ADRs, MasterPlans, skills, and repository navigation remain outside the
bundle.

The reusable convention belongs to the central `shinzui/okf-profiles`
repository as `documentation.patternCatalog`. This repository consumes an
immutable tagged and Dhall-hash-pinned release through
`okf/runtime-patterns.dhall`; it does not fork the profile locally.

Each concept keeps its existing Mori DocRef as the stable `resource` join. The
60 existing DocRef keys do not change when paths move, and new concepts receive
new DocRefs. Subject overview prose lives in `overview.md`; every `index.md` is
generated by `okf index` and must not be edited by hand.

A material concept change must update the concept's RFC 3339 `timestamp` and
the nearest enclosing `log.md` in the same diff. Authors run
`scripts/check-runtime-patterns [BASE_REF]`, which enforces core and profile
validation, log freshness and diff pairing, generated-index determinism, and
graph serialization.

## Consequences

- Humans enter through `runtime-patterns/getting-started.md` or generated
  indexes; agents can discover the bundle and concepts through Mori and inspect
  one concept with `okf show`.
- Cross-subject links are validated as one 61-node graph, while execution
  memory and repository administration remain outside the graph.
- Profile changes require an upstream `okf-profiles` release and an explicit
  local pin update.
- Generated indexes are reproducible artifacts. Git's `blank-at-eof` check is
  disabled only for those files because OKF `v0.1.2.0` canonically emits a
  trailing blank line.
- A document update without its nearest log fails the diff-aware repository
  check, even though the released OKF command reports that drift diagnostically
  rather than through its exit status.

## Alternatives Considered

**Use the repository root as the bundle.** Rejected because OKF would discover
plans, ADRs, MasterPlans, and agent skills as runtime concepts.

**Create one bundle per subject.** Rejected because the corpus has many
cross-subject links that should remain internal validated graph edges.

**Define a repository-specific profile locally.** Rejected because the
pattern-catalog convention is reusable and has an authoritative versioned home
in `shinzui/okf-profiles`.

**Replace DocRefs with new concept URIs.** Rejected because existing DocRef keys
are already stable cross-repository identities, while Mori concept discovery is
live and bundle-scoped.
